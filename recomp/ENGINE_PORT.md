# Engine port (EXE.1 -> Rust/Bevy) — plan and worker protocol

Goal: a playable Bevy build. The game-logic modules are ported (see PORT_NOTES.md); they talk to the engine
through the `Host` trait (recomp/src/engine/api_gen.rs, 480 API fns in 21 groups) plus the engine core already
in recomp/src/engine/core. What is missing is the **engine itself**: EXE.1 (`Decompiled Source/EXE.1 - Game
Engine/`, C++ with full symbols, 6,916 fns; classes in `Classes/{DT,EF,EFDM,EFFB,PL,EI,Other}`; RenderWare 3.4 in
`RenderWare/`).

Rules (same as the logic port): 1:1 where the code is game-specific (same names, same semantics, quirks kept and
commented). RenderWare/Sony-SDK/libc internals are NOT ported 1:1 — they are replaced by Rust/Bevy equivalents
(wgpu rendering, bevy_audio/kira, gilrs input) behind the same engine-facing functions. Bevy conventions:
engine state in Resources, no global state, no blocking I/O inside systems (asset loading is done up-front per
level or via Bevy AssetServer).

## Asset inventory (ISO `work/iso_listing.txt`)
LEVEL/<EP>/<Lnn>/GEN/<name>.P2R: level pack (header `u32 hash,u32 count` then count x {id,size,offset,type};
data base = 8+16*count; see tools/p2r.js for the code-entry layout). Besides the ELF logic modules, the pack
holds the DT descriptors/resources (3D objects, animations, cameras, lights, emitters, sounds, waypoints,
hotspots) that EFRessourcesMgr::LoadLevel / DTStreamFAT / DTBinaryPersistStream read.
LEVEL/<EP>/<Lnn>/EN/: TEXDIC_0.TXD + LOADNTSC.TXD (RenderWare texture dictionaries, PS2 format), FONT0/1.FT+PAL,
GLOBAL.PAL, TEXT.TX (texts), LOAD.LS (loading screen), AUDIO/*.SBB/SBH (sound banks) + *.TSC/TSE (sound tables).
STREAM/: *.VAG (ADPCM audio), *.PSS (movies), *.INT, *.IMG.

## Worker protocol
- Workers are launched by the coordinator chat (max 2 at a time: more hit the API rate limit).
- Each worker gets ONE WP and a brief file tools/engineport/wp_<X>.md. It works in a scratch copy
  (`cp -r recomp /tmp/wp_<X>`), writes new files only under recomp/src/engine/<its module dir> plus one test file
  recomp/tests/engine_<x>.rs, and copies them back ONLY when `cargo build` and `cargo test` pass in the scratch copy.
  Never edit files outside its WP (api_gen.rs, plugin.rs, modules/, other WPs); if an API change is needed, write
  it in the final reply instead.
- Register the module: the coordinator adds `pub mod <x>;` to recomp/src/engine/mod.rs after the copy-back.
- Facts worth keeping (formats, offsets, quirks) go into this file under "## Findings" (append-only), one bullet
  per fact, prefixed by the WP letter.
- Finish with a short final text reply: files written, what is 1:1, what is replaced, what is unported.

#### P2R / FAT facts (verified on real data)
- The P2R file IS a DTStreamFAT binary stream: `u32 version(this+0x38)` then `u32 count(this+0x34)` then count×DTFatRecord{u32 uid, u32 size, u32 offset, u32 classId} (LoadPropertiesBinary: LoadData(uint)×2, SetSize, memset, LoadBinaryData(count*16)). Then entries follow SEQUENTIALLY in the same stream (no seeking); offsets are cumulative from data base 8+16*count. EP1L01.P2R: version 0x1dbb4, 471 entries, seq ok, end==file size 13502603; types {0x18:1,0x1f:1,0x24:1,0x27:41,0x30:9,0x3c:1,0x45:11,0x48:1,0x49:9,0x4f:294,0x52:1,0x5b:101}. - Code entry sub-layout (tools/p2r.js): `{u32 id(UID), u32 arg, u32 nameLen, char name[nameLen] ('.' stored as '\0')} then ELF`; nameLen 4/20/36, stale bytes after first NUL.

## WP-L19 findings: c2rs converter

- `tools/rustport/c2rs.py <family> <rust_mod> <module dirs...>` converts the Ghidra C of every build in a family into `recomp/src/modules/<mod>/`. It writes one `b_<sha8>.rs` file per distinct code and a `mod.rs` containing the ModuleDef (data_size = largest build), `KEYS`/`build_index`, ctor/dtor dispatch on `e.rt.cur_build()`, and `build_init` with each build's initialised data image (.text words, rodata string relocs, data-relative relocs).
- Globals become `g(e, addr)` (cur_data-relative). Stack locals whose address is taken, or that Ghidra names as stack variables, live in one `e.alloca` frame at their Ghidra stack offsets, so struct and array aliasing matches the PS2. Integer arithmetic wraps. Signedness follows C promotions. API calls use the api_gen.rs trait signatures (with `?` on LResult).
- Anything it cannot convert becomes a `todo!("c2rs: ...")` (goto, calls through code pointers/function-pointer data, unknown fields, Ghidra CONCAT/SUB ops) and is counted in the file header. `tests/logic_l19.rs` (FAMILIES list) links every level pack and runs each object of the generated families for 3 frames, each under its own catch_unwind. The test fails if any build is still unported or panics. It caught `teleport_lockdown`, which calls through a function pointer stored in data (word 0x27bdffe0 = the callee's prologue). That family stays unported until fixed by hand.
- Workflow: generate, `cargo build`, hand-fix compile errors and todo!s, add to logic_link.rs, modules/mod.rs and the logic_l19 FAMILIES list, verify in a HEAD worktree with only the staged diff applied, then commit.
- Repo files use CRLF in the index. When editing staged blobs via `git hash-object`, keep CRLF or the whole file shows as churn.
- Coverage at HEAD a56ef092 (from a clean worktree): 231 unported modules (289 builds), down from 333 (643) at the start of WP-L19.

## A4 (WP-A4: interleaved stereo .INT music)
- Format: 0x30-byte header `A2M\0PS2\0`, +0x10 rate BE (44100), rest 0; body = SPU ADPCM interleaved L,R in 0x6000-byte chunks (L0 R0 L1 R1 ..; all bodies are multiples of 0xC000; no ADPCM loop/end flags). Each channel decodes continuously (history across chunks).
- Interleave source: EE SOUND_PlayInterleavedStream (0x00248fd0) -> SOUND_SetStreamParent_Int(stream, 0, 0x6000) (IOP cmd 0x2b); AllocateStereoStreamMemory: IOP buffer 0x18000 (= 2 ch x 2 halves x 0x6000), SPU 0x2000 (child voice at +0x1000, SOUND_ResizeSPUBuffer 0x1000). Empirical: L/R correlation only at 0x6000 (EP1L1 0.73, MUMENU 0.55; 0x800..0xC000 all |c| < 0.14), chunk-boundary jump/avg step 0.7-1.6. IRX not disassembled (not needed).
- Loop: SBH stream sample record +0x84 (PS2bodyTableRecord+0x84, passed to SOUND_PlayStream) = driver loop flag: 1 for MU*.INT music + MUMenu + FXMOVIE.VAG, 0 for CS*.INT cutscenes / voice VAGs. Port: mgr sets Voice::looped for stream samples with +0x84 != 0; AdpcmStream restarts at the body start at data end when looped.
- Port: spu::SpuData::Interleaved(file, ch) / AdpcmStream::interleaved (logical->file offset mapping); stream::load_stream_adpcm keeps the whole A2M file (rate from +0x10); game.rs spawn_spu_voice gives side 0/1 channel 0/1. Test tests/engine_a4.rs (MUEP1L1 + MUMENU: corr, boundary continuity, rms, loop restart, one-shot length; WAV via A4_WAV_DIR).
